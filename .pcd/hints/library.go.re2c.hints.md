# Hints: library.go.re2c

Template:  library
Language:  Go
Library:   re2c (https://re2c.org)
Version:   4.6
Release:   2

`Version` is the version of the tool. `Release` counts the changes of this
file since `Version` was last set; a new version of the tool removes the
line.

re2c is a lexer generator. It reads rules with regular expressions and
writes a tokenizer as Go code. It is a tool of the build. The tokenizer
that it writes imports no package. Every statement in this file was run
with re2c 4.6 and with re2c 3.1, and with Go 1.24.7.

---

## Verified version and call

```
$ re2c --version
re2c 4.6

$ re2c --lang go -8 -i --no-generation-date lexer.re -o lexer.go
```

- `--lang go` selects Go. The program `re2go` writes the same file. The
  call above needs the program `re2c` only.
- `-8` makes a tokenizer for text in UTF-8. The tokenizer reads bytes, and
  the classes in the rules are classes of characters.
- `-i` stops the `//line` directives. Without it the file has the name of
  the input file in many lines.
- `--no-generation-date` is needed. Without it the first line of the file
  has the date and time of the call, and the file is different for every
  build.
- With these options the first line of the file is
  `// Code generated by re2go 4.6, DO NOT EDIT.` It names the version of
  re2c. A file from another version is therefore never the same file.
- Do not edit the file and do not run `gofmt` on it.

The version decides the classes of characters. The file
`unicode_categories.re` comes with re2c, and it has the classes of one
Unicode version. From re2c 4.5 on this is Unicode 17.0.0.

## The input file

The input file is a Go file with blocks for re2c. A function with one
block is one tokenizer:

```go
package aql

/*!include:re2c "unicode_categories.re" */

func peek(s string, cur, lim int) byte {
	if cur < lim {
		return s[cur]
	}
	return 0
}

// lexStrict finds the rule for the place start. It returns the kind of
// the rule and the place after the run.
func lexStrict(s string, start int) (int, int) {
	lim := len(s)
	cur := start
	mar := start
	_ = mar
	/*!re2c
	re2c:define:YYCTYPE = byte;
	re2c:define:YYPEEK = "peek(s, cur, lim)";
	re2c:define:YYSKIP = "cur += 1";
	re2c:define:YYBACKUP = "mar = cur";
	re2c:define:YYRESTORE = "cur = mar";
	re2c:define:YYLESSTHAN = "lim <= cur";
	re2c:yyfill:enable = 0;
	re2c:eof = 0;
	!include "tokens.re";

	spaces           { return rowSkip, cur }
	word             { return rowWORD, cur }
	$                { return rowEnd, cur }
	any              { return rowNone, cur }
	*                { return rowNone, cur }
	*/
}
```

- Write the eight lines that start with `re2c:` in every block, as they
  stand here.
- `re2c:eof = 0` and the helper `peek` let the tokenizer read a string
  without an end mark. A NUL character in the text is read like every
  other character.
- `_ = mar` keeps the Go compiler quiet when the generated code does not
  use the variable.
- `/*!include:re2c "unicode_categories.re" */` stands once, before the
  first block. It gives the names of the Unicode general categories, for
  example `L` and `Z`.
- `!include "FILE";` inside a block takes definitions from a file of the
  same directory. A definition is `name = regular expression;`.
- Definitions stay for all later blocks of the file. Include a file of
  definitions in the first block only. A second include is an error:
  "name 'digit' is already defined".
- A rule is a name or a regular expression, then Go code in braces. The
  code returns from the function.

---

## Which rule wins

- The rule with the longest run wins.
- When two rules have the same run, the rule that stands first wins.
- `$` is the rule for the end of the text. Put it after the rules for
  tokens.
- `any` in the example is a definition, `any = [^];`, for one character of
  any kind. As the rule after `$` it takes a character that starts no
  token.
- `*` is the default rule. In a tokenizer for UTF-8 it takes one byte that
  is not the start of a character, for example the byte `0xFF`.

A byte that is not valid UTF-8 never matches a class of characters. A
pattern like `[^'\\]` does not take it. Text with such a byte therefore
ends a run early, and another rule can win at that place.

---

## Two tokenizers in one file

A second function with a second block gives a second tokenizer, for
example with other patterns for some rules. Each block has its own eight
`re2c:` lines and its own list of rules. The definitions come from the
first block.

---

## Size and time

The class of all letters, `L`, needs many states in a tokenizer for UTF-8.
The test file had two tokenizers of 18 rules each, and several patterns
used `L`. It had 1.5 MB with re2c 4.6 and 1.3 MB with re2c 3.1. The Go
compiler needed about 35 seconds for it. The tokenizers themselves are
fast: both together read 40000 short texts in less than 0.1 seconds.

---

## Known gotchas

- No call without `--no-generation-date`.
- No second `!include` of the same definitions.
- No `gofmt` on the generated file.
- No change of the re2c version without a new generated file: the first
  line and the classes of characters change with it.
- No use of the `regexp` package beside the tokenizer to decide what a
  token is. The rules decide it.
- re2c writes its output file with the mode 0600, whatever the umask is.
  Set the mode after the call, for example with `chmod 644 lexer.go`.
  Otherwise a tarball of the working tree has a file that only its owner
  can read.
