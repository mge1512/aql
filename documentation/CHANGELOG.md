# Changelog of libaql.spec.md

- 2026-11-28: Version 0.7.0. This Version answers the findings of the first translation to Go, which was made from Version 0.6.0. parse-statement now refuses a text that is not valid Unicode text, with the new message S21 and before the length check. The two checks of step 1 keep no copy of the text. S02 and W08 now say what to send. A run that starts like a number or a date and is neither now gets the message S13 with the run. Before, it had S02 with its first character. Six rules are written down as the translation read them, or as they were meant. A condition in parentheses stays one member. C02 and C07 read a number as it is written. C12 and C13 look at every token after WHERE. Capital letters change the letters a to z only. The cut at MaxEcho is for every placeholder that repeats a word. After a cut name the three periods take the place of the period that follows. tokenize, check-forms and syntax-messages changed as a consequence of these points, and six examples are new.
- 2026-11-27: Version 0.6.0. The token table of tokenize is now written in the notation of the lexer generator re2c: a block of definitions and a list of rows. Before, the specification had a notation of its own. Every row matches the same texts as before. The kinds and the order of the rows are the same, so the language does not change. The row space has the new name spaces, because space is also a class of characters. DEPLOYMENT now says that the specification names two tools for their notation only. It also says that a translator takes the definitions and the grammar over as they are.
- 2026-11-27: Version 0.5.0. The tokenizer now always comes from a lexer generator at build time. A regular expression engine at run time is no longer a choice, because the bindings take one lexer generator for all target languages. The last exception for a library at run time is therefore removed. An implementation uses the standard library of its target language and no other library.
- 2026-11-27: Version 0.4.0. The grammar of parse-statement is now written in the notation of the Lemon parser generator, one line for each alternative. Before, it was written in the notation of yacc. The 94 alternatives and their order are the same, so the language does not change. A parser generator for this notation reads the block as it is. The build check can compare the grammar of an implementation with the block as text.
- 2026-11-27: Version 0.3.0. The bindings take lemongrass as their parser generator, and its parser needs the standard library only. The run-time exception for the support code of a parser generator is therefore removed, and the exception for a regular expression engine stays. The constraint for the generated parser has a new rule: a limit of its stack is above what a statement with MaxTokens tokens needs. The new example statement_at_the_token_limit reads a statement with 992 NOT in a row.
- 2026-11-26: Version 0.2.0. The specification no longer assumes one target language. A language may add two things at run time when its hints name them. They are a regular expression engine, where its standard library has none, and the support code of a parser generator. A lexer generator may build the tokenizer. In the lenient patterns the added alternative now stands first. Every pattern then gives the same run in an engine that takes the longest run and in one that takes the first alternative. ParseStatement gives a Statement or an AqlError, no longer a pair of both. An implementation writes the names of the interface in the style of its target language.
- 2026-11-26: Version 0.1.0. First Version, with the front end of the library: token table, grammar, limits, and the messages for a statement that cannot be read. The language is the one of aha-aql 0.24 with a JOIN of two entities, IN with a subquery, HAVING and MATCH. No name is looked up yet; the rules for names, the evaluation, the adapter contract and the shell follow in later Versions.
